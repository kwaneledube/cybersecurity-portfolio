Putting my portfolio online with DNS and security headers

DNS · CNAME · Vercel · HTTP security headers

Goal

Publish a portfolio on a free subdomain of a domain I already own (isizuluai.co.za), then harden it so it passes a public security headers scan.

Tools and environment

GitHub, Vercel (free Hobby plan), TrueHost DNS management, and securityheaders.com for testing.

Steps

  1. Created a public GitHub repo called cybersecurity-portfolio and uploaded the static site files. The repo holds no passwords or keys, so public is safe.
  2. Imported the repo into Vercel and deployed it. Vercel gave me a temporary .vercel.app address to check the site first.
  3. Added portfolio.isizuluai.co.za under Domains in Vercel. Vercel then showed the CNAME value it expected.
  4. At TrueHost, added a CNAME record with the name portfolio pointing to that Vercel value. The site was live within minutes, and Vercel switched on HTTPS automatically.
  5. Added a vercel.json file so every response carries six security headers (listed below).
  6. Scanned the site at securityheaders.com and got an A+.

The six headers and what each one does

  • Content-Security-Policy: tells the browser which sources of scripts, styles and images are allowed, which limits injected-script attacks.
  • Strict-Transport-Security (HSTS): tells browsers to use HTTPS only for this site, which blocks downgrade attacks.
  • X-Frame-Options: stops other sites from putting mine inside a frame, which prevents clickjacking.
  • X-Content-Type-Options: stops the browser guessing file types, which prevents some content-sniffing attacks.
  • Referrer-Policy: limits how much of my URL is shared when someone clicks a link off my site.
  • Permissions-Policy: switches off browser features I don't use, such as camera, microphone and location.

What went wrong

When adding the domain in Vercel, I typed it into the search box instead of clicking Add Existing. The search box only filters domains already added, so it showed "No Results Found". The lesson: read the button labels, because searching a list and adding to it are different actions.

What I learned

  • A domain is the name I rent, hosting is the computer that serves the files, and DNS is the phone book connecting the two.
  • A subdomain of a domain I own costs nothing, because it is just one more DNS record.
  • A CNAME makes one name an alias for another, so visitors to my subdomain are sent to Vercel.

Defender's view

  • Security headers reduce several common browser-side attacks, but an A+ only says the headers are set. It does not make a site unhackable. This is a static site with a very small attack surface.
  • Dangling DNS is a real risk. If I ever delete the Vercel project but leave the CNAME record in place, an attacker could claim the name on that hosting service and serve content from my subdomain. This is called a subdomain takeover. The fix is simple: remove the DNS record whenever I stop using a service.
  • Next improvement: review DNS records for anything pointing to services I no longer use.
