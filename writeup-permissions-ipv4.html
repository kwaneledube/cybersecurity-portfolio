Linux permissions and IPv4 basics

chmod · least privilege · /etc/shadow · IPv4 · network vs host

Goal

Learn how Linux decides who can read, change and run a file by changing permissions myself and watching the result. Alongside it, learn how an IPv4 address splits into a network part and a host part (Cisco Networking Basics, Module 8).

Tools and environment

Kali Linux on WSL2 (isolated from my Windows drive), working inside a practice folder in my own home directory. For IPv4, the Cisco Networking Academy course.

Part 1: the permissions lab

  1. Created a practice folder and an empty file with touch, then checked it with ls -l. The default mode was -rw-r--r-- (644): the owner can read and write, everyone else can only read.
  2. Ran chmod 600 on the file. The mode became -rw-------, so only the owner has any access.
  3. Ran chmod 777 to see the red-flag case. The mode became -rwxrwxrwx, so every user could read, change and run the file. Then I set it back to 644.
  4. Created a one-line script and tried to run it with ./hello.sh. Linux answered Permission denied, because the file had no x (execute) permission for anyone. Adding execute for the owner with chmod u+x fixes that.
  5. Compared two real system files with ls -l:
-rw-r--r-- 1 root root   /etc/passwd
-rw-r----- 1 root shadow /etc/shadow

/etc/passwd lists user accounts and is readable by everyone. /etc/shadow holds the password hashes and gives "others" no permissions at all, so cat /etc/shadow as a normal user returned Permission denied.

Part 2: IPv4, network and host

  • An IPv4 address is 32 bits, written as four octets of 8 bits each. An octet has 256 possible patterns, so it runs from 0 to 255.
  • The subnet mask shows which bits are the network (the 1s, shown as 255) and which are the host (the 0s). With mask 255.255.255.0, the address 192.168.1.10 has network portion 192.168.1 and host portion 10.
  • Two devices can talk directly only if their network portions match. 192.168.1.10 and 192.168.2.20 do not match, so traffic between them must go through a router, the default gateway.
  • To read an octet in binary, add the values of the bits that are switched on (128, 64, 32, 16, 8, 4, 2, 1). For example 11000000 is 128 + 64 = 192.

What went wrong

  • I read the wrong line of output. When asked for the permissions after chmod 600, I gave the mode from before the change. Lesson: look at the output that comes after the command, and compare it with the line before to see what changed.
  • I mixed up what x means. On a file it means run it. On a directory it means enter it. Lesson: ask what kind of object I am looking at before reading the letters.
  • I confused bits with octets, and network with host. I first said an IPv4 address is 8 bits and that the last number is the network portion. Lesson: a mask of 255 means network and 0 means host, and the address is four octets of 8 bits, which makes 32.
  • I read binary like a decimal number. I wrote 00001010 as "1.010". Lesson: treat it as a row of switches, and add the values of the ones that are on (8 + 2 = 10).

What I learned

  • A mode has three sets (owner, group, others), and each set can have read (4), write (2) and execute (1). So 644 is rw-r--r-- and 600 is rw-------.
  • Permissions work on directories too, with different meanings: r lists the names, w creates or deletes items inside, and x lets me enter.
  • "Permission denied" is the system doing its job, not a fault.
  • The network and host split decides whether two devices can talk directly or need a router.

Defender's view

  • Least privilege. Files should be readable and writable only by whoever needs them. A world-writable file (777) lets any user, or any process running as a user, change it, and attackers look for exactly that.
  • Protecting credentials. Splitting user names (public) from password hashes (restricted) means that reading the user list does not hand over the passwords. If a shadow file ever became readable, an attacker could copy the hashes and crack them offline.
  • Check permissions as part of hardening and auditing. ls -l on sensitive files, and a search for world-writable files, are basic checks a defender can run.
  • Sudo is power. My account is in the sudo group, so I can run commands as root. That should be used deliberately, for things I understand.
  • Network separation. Putting devices on different networks, with a router or firewall between them, limits what a compromised device can reach directly.
